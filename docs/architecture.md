# Project structure

The portfolio uses Next.js with a static export and Sanity Studio. Application source is under src, colocated by feature. Run commands with Yarn.

## Root folders

| Folder         | Responsibility                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| src            | Application source, CMS schemas, and the isolated project demo.                                        |
| public         | Files served directly: branding assets and generated PWA/demo files.                                   |
| scripts        | Five commands supporting demo builds/sync, PWA icons, Studio packaging, and the static preview server. |
| docs           | Architecture, CMS, contact, localization, and Steam setup notes.                                       |
| .vscode        | Shared editor extensions and formatting settings.                                                      |
| .openai        | Existing Sites hosting identity and static output configuration.                                       |
| .git           | Repository history.                                                                                    |
| .yarn          | Yarn-managed local installation state.                                                                 |
| node_modules   | Installed dependencies; regenerated by yarn install.                                                   |
| .next          | Next.js cache and intermediate build output.                                                           |
| out            | Deployable static website, including out/studio. yarn start serves this folder.                        |
| studio-dist    | Intermediate Sanity Studio build, copied into out/studio.                                              |
| .sanity        | Sanity-generated files.                                                                                |
| .sites-runtime | Ignored local tooling, screenshots, and browser verification files. Not shipped.                       |

Generated folders are ignored by Git. They reappear when installing dependencies or building; they are not application source.

Root configuration files configure Next.js, TypeScript, ESLint, Prettier, Tailwind/PostCSS, Sanity, shadcn, and Yarn. .env.local contains private build configuration and is ignored by Git. AGENTS.md and CLAUDE.md contain coding-agent guidance.

## Data and responsibilities

Feature repositories retrieve and validate external data. Components render the result. Hooks connect React lifecycle and state to behavior. Browser controllers own canvas listeners, animation, and observers.

Hero: PixelHero → usePixelHero → pixel-hero-controller → life-player and pixel-renderer.

Projects: ProjectCanvas → useProjectExpansion → project-transition. JsonRendererDemo validates messages from the isolated iframe and adjusts its height.

Theme: ThemeToggle → useTheme → theme-store.

Use relative imports within a feature and @/ imports across features. The alias resolves to src. SRP means one reason to change, not one file per trivial operation.

## Build flow

1. Generate PWA assets from the logo and src/features/pwa/assets.
2. Bundle the JSON renderer demo into public/demos/json-renderer.
3. Export Next.js pages into out, retrieving published Sanity content and Steam data during the build.
4. Build Sanity Studio into studio-dist and copy it into out/studio.

The main application uses React 19; the isolated demo uses React 18 for upstream compatibility. One Yarn lockfile manages both workspaces. Edit demo source, not generated public/demo bundles. Preserve upstream licensing and provenance.

The former Vite/Cloudflare runtime, database examples, Drizzle integration, unused starter UI packages, and obsolete installer scripts have been removed. The portfolio does not require a separate SQL database.
